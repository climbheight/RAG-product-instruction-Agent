## 一、这是什么任务，为什么必须做

本课题是「基于产品文档的大模型智能体」。系统要回答用户关于产品操作的问题，
**答案下面必须配手册原图**（课程硬性要求，不能是模型生图）。

但检索图片有个根本障碍：

> **BGE `bge-small-zh-v1.5` 只能嵌入文本，图片本身不能嵌入。**

所以每张图必须配一段**可检索文本**（`search_text`），格式是：

```
【产品名】章节 第N页插图。画面：<VLM描述> 说明：<邻近文本> 图中文字：<OCR/矢量取字>
```

其中「画面」这一段**只能靠人（或视觉模型）看图写出来**——OCR 只能读出图里的字，
读不出"这张图画的是什么、说明哪一步操作"。

**这就是标注任务的全部意义：把 874 张图变成 874 段能被人提问命中的文字。**

## 四、标准作业流程（照着做就行）

### 步骤 1：看进度，选产品

```bash
cd "E:/code/软件课设智能体"

$P scripts/annotate_batch.py --status
```

**一个产品一批做完再换下一个**，不要跨产品混批（容易搞错映射）。

### 步骤 2：生成九宫格

```bash
$P scripts/annotate_batch.py --doc <doc_id> --limit 9
```

输出两样东西：
- `montage: ...\batch_<doc_id>_000.png` ← 要看的图
- `映射: {"1": {"figure_id": "...", "section": "...", "nearby": "..."}, ...}` ← 编号对应关系

**排序规则**：按 `search_text` 长度升序，也就是**文本最弱的图排前面**——
这些图最需要描述，优先做。

### 步骤 3：看九宫格（用 Read 工具打开 png）

**不要用代码跑 OCR 代替看**，必须真的看图。

### 步骤 4：三档分类（两级策略的核心）

| 档位 | 特征 | 处理 |
| --- | --- | --- |
| **A 类** | 整机外观、单个部件、单个箭头、单个界面 | 粗看即定稿 |
| **B 类** | 参数表、接线图、多图拼接、密集界面、需看清文字 | **必须读原图** |
| **X 类** | 页眉横线残片、二维码、品牌 Logo、纯文字误判块 | 标 `无效图块：<原因>` |

判定口诀：
> 能一眼看出"这是什么图、说明什么操作"的 → A 类；
> 需要看清"第 3 个按钮叫什么""参数表第 5 行是多少"的 → B 类。

### 步骤 5：B 类读原图

```python
Read(file_path="E:/code/软件课设智能体/data/extracted/<doc_id>/images/<figure_id>.png")
```

读**原图**，不是九宫格缩略图。重点核对：
- 界面控件名称、按钮文字
- 参数数值（电压、功率、温度、尺寸）
- 标注序号 ①②③ 的对应关系
- 箭头方向
- 正误对比图哪边是对的

### 步骤 6：写回

```python
from src.ingestion.annotate import apply_captions
doc = "<doc_id>"
caps = {
    "<figure_id>": "<一句话描述>",
    ...
}
print("写入:", apply_captions("data/extracted", doc, caps))
```

`apply_captions` 会自动重算该图的 `search_text`（把新描述拼进去），
不需要手动改。

```bash
git add -A
git commit -m "feat(annotate): <产品名> 标注 <N>/<M>"
git push origin main
```

## 五、标注规范（硬要求）

### 5.1 必须结合全文，不能只看图

每张图的描述必须建立在三类上下文之上：

1. **章节与位置**：`section`、`page`、`doc_title` → 确定属于哪个功能
2. **前后文**：`nearby_text` → 这一步在讲什么操作
3. **图内文字**：`ocr_text` → 校准部件名、按钮名、界面文案

九宫格输出的映射表里已经带了 `section` 和 `nearby`，直接用。
必要时回查 `chunks.jsonl` 里该图的 `chunk_ids` 对应段落。

### 5.2 写法

- **一句话中文，30~60 字**
- 先说「这是什么图」，再说「它说明/标注了什么」
- 用**手册里的术语**（机臂、云台、表耳卡扣、衣帽挂钩），不要自造词
- 界面截图写出**关键控件 + 当前状态**（"已连接""高亮选中""83% 进度"）
- 操作示意图写出**动作与方向**（"沿箭头向上拔出""长按 2 秒"）
- 重复出现的图注明「与第 N 页重复」

### 5.3 好 / 坏示例（都是真实案例）

**✅ 好**

```
"第二排座椅头枕拆卸示意，蓝色箭头指示向上拔出头枕的方向"
"打印中界面截图：显示打印进度 83%、文件名 rabbit、已用与剩余时间、
 喷头 200℃ 与热床 60℃，以及设置、暂停、停止按钮"
"指关节滚动截长图：单指指关节敲击并画 S 形，屏幕自动向下滚动截取长图"
"主板俯视图与红框放大图，标注①②③固定螺丝位置以及 M.2 固态驱动器的插入方向"
```

**❌ 坏**

```
"一张图片"                          ← 没有信息，检索永远命中不了
"图1"                              ← 编号对用户无意义
"这是关于座椅的图"                  ← 太泛，和几十张图撞车
"展示了产品的先进设计理念"          ← 手册里没这句话，属于编造
"图中按钮可能是设置"                ← 看不清就说可能，会污染检索
```

### 5.4 无效图块

遇到垃圾块，格式固定为 `无效图块：<具体原因>`：

```
"无效图块：页眉横线残片（“整机清洁”标题栏），非插图"
"无效图块：二维码，非插图"
"无效图块：纯文字段落被误判为插图，非图片"
"无效图块：Midea 品牌标志（装饰图，非操作示意）"
```

**为什么重要**：`src/retrieval/build.py` 在建索引时会自动剔除
`vlm_caption` 以「无效图块」开头的条目。等于**标注同时承担质量审查**。
不标的话，这些垃圾会进向量库污染召回。

## 六、必须知道的坑

### 坑 1：九宫格会裁切，导致误判

340px 的格子装不下长条形或超宽的图，会被裁掉边缘。
**实测案例**：问界 M9 的「衣帽挂钩」两张图，九宫格里只看到车内座椅，
蓝色标记被裁没了，粗筛完全判断不出挂钩在哪。读原图才发现标记在 **B 柱上方**。

→ 凡是在格子里"看不全"的，一律进 B 类读原图。

### 坑 2：编号可能和映射错位

`make_montage` 遇到图片文件缺失会**跳过**，但编号不重排，导致
九宫格上的「3」实际对应映射表里的「4」。

→ 生成后先核对文件是否齐全：
```python
for i, r in enumerate(todo[:9], 1):
    print(i, r['figure_id'], os.path.exists(path))
```

### 坑 3：不要凭 nearby_text 编造画面

`nearby_text` 是邻近的文字，**不一定是这张图的说明**。
比如某图旁边是「配图仅供参考」，你不能写"这是配图仅供参考的图"。

→ 图里看不到的就不写。宁可描述简单，也不要编。

### 坑 4：同一产品内的重复图

手册经常把同一张图放在不同章节重复出现（如大疆 Mimo App 下载页、
华为分享示意）。按规范注明「与第 N 页重复」，不要当成新图另写一遍。

### 坑 5：宇树 G1 的切分质量差

宇树 G1（56 张）和美的电饭煲（5 张）是扫描页版面切分出来的，
**质量明显差于其他产品**。实测宇树 9 张里只有 4 张是有效插图，
其余是页眉横线残片、纯文字误判、二维码、品牌 Logo。

→ 遇到这类直接标 `无效图块`，不要试图描述。重做切分会改变
`region_no` 编号，导致已标内容全部失效，所以**现阶段不重做**。

### 坑 6：git 上有并行会话

仓库有多个 worktree，别的会话可能在同时改同一批文件。
提交前先 `git status` 看一眼，有意外文件先问清楚再提交。

## 八、字段说明（`figures.jsonl` 每行）

| 字段 | 含义 | 谁写 |
| --- | --- | --- |
| `figure_id` | 唯一 ID，如 `dji_mic2_p010_f03` | 解析器 |
| `doc_id` / `page` / `bbox` / `path` | 来源与位置 | 解析器 |
| `source` | `raster` / `vector` / `page-scan` | 解析器 |
| `section` | 所属章节 | 解析器（按阅读顺序找最近标题） |
| `nearby_text` | 邻近说明文字 | 解析器 |
| `ocr_text` | 图内文字（OCR 或矢量取字） | 解析器 |
| **`vlm_caption`** | **看图写的描述** | **← 你要填的** |
| `search_text` | 送嵌入的文本 | `apply_captions` 自动重建 |
| `chunk_ids` | 反向连接：哪些 chunk 引用了它 | 解析器 |
| `embedding_ref` | 嵌入引用 | 解析器 |

## 九、禁止事项

1. **禁止写代码自动生成描述**。必须真的看图。写脚本批量填"图"、"示意图"
   这类占位词，等于没做，而且会污染向量库。
2. **禁止跨产品混批**。一个产品做完再换。
3. **禁止凭 `nearby_text` 猜画面**。看不到的不写。
4. **禁止改 `region_no` 相关的切分逻辑**。会让已标内容失效。
5. **禁止跳过「无效图块」标记**。垃圾进库会拉低检索质量。
6. **禁止一次提交多个产品**。按产品粒度提交，便于回溯。
